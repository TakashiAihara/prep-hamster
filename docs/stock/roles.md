# ロール定義

> グループ単位の権限制御（RBAC）における各ロールの責務と境界を定義する恒久ドキュメント。
> 権限変更の判断はすべて本書を起点とする。詳細仕様（API・UI 制御）は別途 flow ドキュメントで詰める。

## 1. ロール一覧

| ロール   | 識別子   | 概要                                                           |
| -------- | -------- | -------------------------------------------------------------- |
| オーナー | `OWNER`  | グループの全操作が可能。少なくとも 1 名の存在を保証する        |
| 編集者   | `EDITOR` | 在庫の追加・変更・消費・廃棄が可能。グループ運用には関与しない |
| 閲覧者   | `VIEWER` | 在庫の閲覧のみ可能。書き込み操作はできない                     |

## 2. 権限マトリクス

凡例: ✅ 可 / ❌ 不可 / 〇 自分のもののみ可

| 操作                                       | OWNER | EDITOR | VIEWER |
| ------------------------------------------ | :---: | :----: | :----: |
| **在庫**                                   |       |        |        |
| 在庫の閲覧                                 |  ✅   |   ✅   |   ✅   |
| 在庫の追加（手入力 / バーコード）          |  ✅   |   ✅   |   ❌   |
| 在庫の編集                                 |  ✅   |   ✅   |   ❌   |
| 在庫の消費（数量減）                       |  ✅   |   ✅   |   ❌   |
| 在庫の廃棄                                 |  ✅   |   ✅   |   ❌   |
| 在庫の削除（論理削除）                     |  ✅   |   ✅   |   ❌   |
| **マスタ（カテゴリ・保管場所）**           |       |        |        |
| マスタの閲覧                               |  ✅   |   ✅   |   ✅   |
| マスタの追加・編集                         |  ✅   |   ✅   |   ❌   |
| マスタの削除                               |  ✅   |   ❌   |   ❌   |
| **必要備蓄量**                             |       |        |        |
| 必要備蓄量の閲覧                           |  ✅   |   ✅   |   ✅   |

| メンバーの招待（招待リンク発行）           |  ✅   |   ❌   |   ❌   |

| メンバーの削除                             |  ✅   |   ❌   |   ❌   |

| **通知**                                   |       |        |        |
| 自身の通知設定の変更                       |  ✅   |   ✅   |   ✅   |

## 3. ロール特有のルール

### 3.1 OWNER

- グループには **常に 1 名以上の OWNER が存在しなければならない**。
- 最後の OWNER が脱退・降格しようとした場合、操作は拒否される（先に他メンバーを OWNER に昇格させる必要がある）。
- グループの作成者は自動的に最初の OWNER となる。
- OWNER 同士に上下関係はなく、相互に降格・削除も可能（最後の 1 名を除く）。

### 3.2 EDITOR

- 在庫操作の主たる担い手。グループ運営の判断（誰を入れるか・出すか・削除するか）には関与しない。
- マスタの「削除」のみ OWNER 権限としているのは、削除がカテゴリ・場所をまたいで影響を与えるため。

### 3.3 VIEWER

- 読み取り専用ロール。例: 同居しない家族が状況だけ把握したい場合、子どもが在庫を確認したい場合など。
- 自分宛の通知設定は変更できる（プッシュを受け取るかどうかは閲覧者本人の選択）。

## 4. ロール変更ルール

| 変更パターン       | 実行可能なロール    | 制約                                |
| ------------------ | ------------------- | ----------------------------------- |
| OWNER → EDITOR     | OWNER（自身を含む） | 降格対象が最後の OWNER の場合は拒否 |
| OWNER → VIEWER     | OWNER（自身を含む） | 降格対象が最後の OWNER の場合は拒否 |
| EDITOR → OWNER     | OWNER               | 制約なし                            |
| EDITOR → VIEWER    | OWNER               | 制約なし                            |
| VIEWER → OWNER     | OWNER               | 制約なし                            |
| VIEWER → EDITOR    | OWNER               | 制約なし                            |
| 任意ロールから削除 | OWNER               | 最後の OWNER を削除する操作は拒否   |

## 5. 招待時のロール付与

- 招待を発行する OWNER が、招待時にロール（OWNER / EDITOR / VIEWER）を指定する。
- 招待リンクには有効期限と使い切り設定を持たせる（詳細は flow ドキュメント側で定義）。
- 招待先がリンクを使用してグループに参加した時点で `Membership` が作成される。

## 6. 複数グループ所属時の挙動

- 1 ユーザーは複数グループに所属できる（v1.0.0）。
- ロールは **グループごとに独立** している。同一ユーザーが Group A では OWNER、Group B では VIEWER ということがあり得る。
- グループ切替 UI を全プラットフォームで提供する（screen-flow.md 参照）。

## 7. 将来の拡張余地（v1.x 以降）

- **カスタムロール**: 既定 3 ロール以外を組織が定義できるようにする。
- **グループのネスト**: 上位グループの OWNER が下位グループも管理できる権限の継承（requirements.md スコープ外参照）。
- **権限の細粒度化**: マスタ削除を EDITOR に開放するためのオプトインなど。
