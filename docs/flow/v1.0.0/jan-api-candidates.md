# JAN コード商品詳細取得 API 候補比較 v1.0.0

> requirements.md 4.3 / data-model.md 3.7 (`ProductMaster.source`) / screen-flow.md 2.3.1 で参照する **外部 JAN API** の候補比較。
> v1.0.0 で第一候補を確定するための判断材料として整備する。flow（流動）扱い。

## 1. 目的と評価軸

### 1.1 目的

- JAN（13 桁 / 8 桁）からの商品詳細取得（商品名・メーカー・内容量・カテゴリ・画像）を実装するため、外部 API を選定する。
- 第一候補 1 つで運用開始 → ヒット率次第で並列照会（多段フォールバック）に拡張可能な構成にする。

### 1.2 評価軸

| 軸             | 説明                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| 提供形態       | API / Web サイト / モバイルアプリ。**公開 API がない場合は本件用途では使えない**。 |
| JAN クエリ     | JAN 専用パラメータがあるか。`keyword` に詰めるしかない場合は実装と精度のリスク。   |
| 認証           | API キーの取得難度・無料枠の有無。                                                 |
| レート制限     | 1 秒あたりリクエスト数。バーコードスキャンの UX に直結。                           |
| 料金           | 無料 / 有料 / 従量課金。                                                           |
| レスポンス情報 | 商品名・メーカー・内容量・画像・カテゴリ・ブランド等の網羅度。                     |
| 商用利用       | 利用規約上の可否。                                                                 |
| キャッシュ可否 | 取得結果を `ProductMaster` にキャッシュして良いか。                                |

| カバレッジ     | 食品・日用品の網羅度（実測は v1.0.0 実装後に評価）。                               |

## 4. 各候補の詳細

### 4.1 C1: Yahoo!ショッピング商品検索 API v3 ★ 第一候補

- エンドポイント: `https://shopping.yahooapis.jp/ShoppingWebService/V3/itemSearch`
- パラメータ: `appid` 必須、`jan_code` で JAN 直接検索、`results` 件数指定。
- レスポンス: 商品名、価格、画像（複数サイズ）、ジャンルカテゴリ階層、ブランド情報、ストア情報。
- レート制限: 1 req/sec。超過すると HTTP 429。
- 料金: 無料。
- 評価: **JAN 直接サポート + 無料 + ドキュメント充実 + 国内最大級の商品 DB**。第一候補にする最も妥当な選択肢。
- 留意点:
  - 出品ベースなのでメーカー・内容量はフィールドにない場合が多く、商品名からの抽出が必要なケースあり。
  - 商用利用条件は別途利用約款の確認が必要（利用規約で「WebAPI の商用利用について」を要参照）。

### 4.2 C2: 楽天商品検索 API / 楽天プロダクト製品検索 API

- 楽天市場商品検索 API: keyword 検索ベース（JAN 専用パラメータなし）。レスポンスに JAN が含まれない場合があり、URL / キャプションから抽出が必要なケースも。
- 楽天プロダクト製品検索 API: 製品マスタ寄りで JAN 検索との相性が良いとの言及あり。
- 料金: 無料（要 Application ID）。
- 評価: **C1 のフォールバック / 補完用途**。並列照会で C1 の取りこぼしを拾う構成が現実的。

### 4.3 C3: JANKEN.jp

- Web フォーム形式の JAN コード商品検索（45/49/978 始まりの JAN/EAN/ISBN 対応）。
- ページが文字化けで詳細取得不可。**公開 API の存在は確認できず**。
- 評価: API として組み込めるかは要問い合わせ。スクレイピングは規約面でリスクが高く非推奨。本件では **当面除外**。

### 4.4 C4: じゃん検索

- 提供元: クラベル (Cravelweb)。スマートフォン向け JAN 検索 & バーコードリーダーアプリ。
- Amazon / 楽天 / Yahoo!ショッピングの価格比較を行うエンドユーザー向けアプリ。
- **第三者向け API は提供されていない**。
- 評価: アプリのため API 統合不可。**除外**。

### 4.5 C5: JANCODE DATABASE (jancode.xyz)

- 6 視点での JAN 検索（番号・キーワード・企業・ジャンル・URL・発売日）。
- データ追加が活発（May 2026 時点で 1 日複数回更新の記載）。
- ページに API 仕様の記載なし。**問い合わせベースでの提供可能性のみ**。
- 評価: 公開 API ではないため即採用不可。**問い合わせ → 評価 → 採用可否判定** の段取り。

### 4.6 C6: JANCODE LOOKUP

- 公開 API を提供（パラメータ: `appId`, `query`, `hits`, `page`, `type`）。
- JAN/EAN/ISBN/UPC に対応。
- クレジット表記必須・レート制限あり（緩和不可と明記）。
- May 2026 時点でサイトが「データ再構築中・近日オープン予定」表示。
- 評価: **再開後の仕様次第**。`ProductMaster.source` に `JANCODE_LOOKUP` を将来的に追加する余地として保留。

### 4.7 C7: GS1 Japan JICFS/IFDB

- GS1 Japan が提供する JAN コード統合商品情報データベース（業界公式）。
- 食品・日用品のカバレッジは最も高いが、業務契約が前提。
- 評価: 個人・小規模サービス向けではない。**v1.x 以降に法人化・課金体系が整ったら検討**。

## 5. 推奨

### 5.1 v1.0.0 採用方針（提案）

- **第一候補: Yahoo!ショッピング商品検索 API v3** で実装スタート。
- **フォールバック: 楽天商品検索 API**（C1 ヒット時の補強として並列照会するかは v1.0.0 の実装フェーズで判断）。
- 残り（JANCODE LOOKUP / GS1 JICFS/IFDB）は **v1.x 以降の拡張枠** として `ProductMaster.source` の enum に余地を残す。

### 5.2 `ProductMaster.source` enum の見直し提案

現行: `YAHOO` / `RAKUTEN` / `JANKEN` / `JAN_SEARCH` / `JANCODE_DB` / `OTHER`

調査結果を踏まえ、API として実装可能な候補に絞った enum に改訂する案:

```
YAHOO_SHOPPING
RAKUTEN_ICHIBA
JANCODE_LOOKUP   -- 再開後に有効化
GS1_JICFS        -- 法人契約締結時に有効化
OTHER
```

`JANKEN` / `JAN_SEARCH` / `JANCODE_DB` は公開 API ではないため、enum 値としては保持価値が低い（必要なら個別問い合わせ後に `OTHER` で扱う）。

### 5.3 次アクション

1. Yahoo Developer Network への登録 → appid 取得。
2. 利用約款の精査（特に **キャッシュ可否** と **商用利用** の文言）。十中八九 OK だが明文化された結論を残す。
3. 楽天デベロッパーへの登録 → Application ID 取得。
4. `ProductMaster.source` enum を data-model.md で改訂（5.2 反映）。
5. JANCODE LOOKUP の再開状況を 1〜2 ヶ月おきにチェック。
