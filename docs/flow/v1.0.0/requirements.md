# 備蓄管理アプリ「prep-hamster」要件定義 v1.0.0

> このドキュメントは flow（流動）ドキュメント。要件は更新されうる前提で v1.0.0 時点のスナップショットを残す。確定した恒久仕様は `docs/stock/` 配下に切り出す。
>
> 本書のスコープは **Why（なぜ作るか）** と **What（何を作るか）** に限定する。How（画面・データモデル・技術スタック等）は別ドキュメント。

## 1. 背景・目的

### 1.1 背景
- 防災備蓄（非常食・水・日用品）を保有していても、賞味期限切れ・保管場所不明で実効性を失うケースが多い。
- ローリングストック（日常消費しながら備蓄を回す方式）を実践したいが、手書きや表計算では運用が長続きしない。
- 複数の住居・家族（自宅と実家など）にまたがる備蓄状況を共有・分担したいニーズがある。
- 災害時はオンライン前提のサービスが使えない可能性があり、オフラインでも在庫が参照できる必要がある。

### 1.2 目的
- 「いつ・どこに・何が・いくつ」を即座に把握できる在庫管理基盤を提供する。
- 消費期限・賞味期限を見逃さず、食品ロスを削減する。
- 家族・複数世帯間で備蓄を共有し、不足を協力して埋められるようにする。
- 防災時にも使える信頼性（オフライン参照・ローカルファースト）を確保する。

### 1.3 v1.0.0 のフォーカス
最初のリリースは **「場所・数・消費期限・賞味期限の管理」** をコアに据える。バーコード登録・通知・共有・履歴・必要量算出はそのコアの周辺機能として揃える。

## 2. ユーザー像 / ペルソナ

### 2.1 一般ユーザー（家族メンバー）
- スマホ中心で、在庫の追加・消費・移動を日常動線でこなしたい。
- バーコードでサッと登録できることを期待。
- 期限切れが近づいたら通知で気付きたい。

### 2.2 グループ管理者
- 家族グループ・複数世帯のオーナー。
- メンバー招待・権限管理・グループ全体のサマリ確認は腰を据えて Web で行いたい。
- 自宅と実家など複数家族をまたいで状況を見たい。

### 2.3 パワーユーザー
- 大量の在庫を一括登録したい、家計簿アプリ等と連携したい。
- スクリプトから備蓄状況を取り出したい。
- CLI 操作に抵抗がない。

## 4. 機能要件（v1.0.0 スコープ）

優先度: **MUST** = v1.0.0 必須 / **SHOULD** = v1.0.0 で実装したい

### 4.1 在庫管理（コア）
- **MUST** 在庫の追加・編集・削除（手入力）。
- **MUST** 在庫項目: 商品名 / 数量 / 単位 / 保管場所 / カテゴリ / 消費期限 / 賞味期限 / 備考。
- **MUST** カテゴリ・保管場所での絞り込み・検索。
- **MUST** 在庫の消費（数量減）と廃棄（期限切れ等）の区別。

### 4.2 期限管理
- **MUST** 消費期限・賞味期限の登録（どちらかのみでも可）。
- **MUST** 期限が近い在庫のアラート通知（モバイル push）。
- **SHOULD** 直近 N 日以内に期限を迎える在庫の一覧表示。

### 4.3 バーコード登録
- **MUST**（モバイル）JAN コード（13 桁 / 8 桁）の読み取りに対応する。
- **MUST** JAN から **商品名・メーカー・内容量** などの SKU 情報を自動取得し、登録フォームを初期化する。
- **MUST** 取得した SKU 情報はサーバ側で横断キャッシュ（商品マスタ）として再利用される（同じ JAN を別グループで読んでも初期値が揃う）。
- **MUST** 商品マスタ・外部参照ともに未ヒットの場合は手入力フォールバック。
- **NOTE** JAN は SKU 単位で発行されるため、内容量・パッケージが違うと別 JAN になる。生鮮食品・量り売り・店舗内コード（02 / 20-29 始まり）は JAN ヒットしない前提で UI 側で手入力導線を確保する。

### 4.4 共有・グループ管理
- **MUST** 1 ユーザーが複数のグループ（家族・世帯）に所属できる。
- **MUST** グループ単位で在庫を共有する。
- **MUST** グループ内のメンバーに権限を付与（オーナー / 編集 / 閲覧）。
- **MUST** 招待機能（招待リンク or メール）。

### 4.5 必要備蓄量・買い物リスト
- **SHOULD** グループ単位で人数 × 日数の必要備蓄量を設定・算出。
- **SHOULD** 必要量に対する不足分から買い物リストを生成・出力。

### 4.6 履歴・分析
- **MUST** 消費履歴・購入履歴の記録。
- **MUST** グラフ表示（消費量推移・カテゴリ別在庫構成など）。

### 4.7 プラットフォーム別の機能配分
| プラットフォーム                | 主対象           | 提供する機能の中心                                |
| ------------------------------- | ---------------- | ------------------------------------------------- |
| モバイルアプリ（iOS / Android） | 一般ユーザー     | 4.1 / 4.2 / 4.3 / 4.5 / 通知・簡易閲覧            |
| Web                             | 管理者           | 4.1 / 4.4 / 4.5 / 4.6 / 一括操作                  |
| CLI                             | パワーユーザー   | import / export・一括登録・スクリプト連携         |

## 5. 非機能要件

### 5.1 データ
- ローカルファースト + クラウド同期。
- 複数デバイス間で在庫の整合性を保つ。
- オフラインでの参照・追記が可能で、復旧時にマージされる（5.3 とセット）。

### 5.2 認証・権限
- ユーザー認証必須。
- グループ単位の RBAC（オーナー / 編集 / 閲覧）。
- 1 ユーザーが複数グループに所属できることを前提とする。

### 5.3 可用性
- **MUST** 災害時を想定し、オフラインで在庫の参照および追記が可能であること。少なくとも直近同期分の在庫はオフラインでも閲覧でき、追記したデータは復旧時に同期される。
- 同期競合時は履歴を残す形で解消する（具体ポリシーは How 側で定義）。

### 5.4 性能
- モバイルで在庫一覧表示まで体感 1 秒以内を目標。
- バーコード読み取りから登録フォーム表示まで体感 2 秒以内を目標。

### 5.5 セキュリティ・プライバシー
- 個人の所有物情報を扱うため、グループ外への漏洩を防ぐ。
- データはユーザー / グループ単位で論理分離。
- 招待リンクには有効期限と使い切り設定を持たせる。

### 5.6 国際化
- v1.0.0 は日本語のみで可。i18n の余地は残す（文言ハードコードを避ける程度）。

## 6. v1.0.0 スコープ外（将来バージョン候補）

- サブスク・定期購入の管理。
- EC サイト連携（自動補充発注）。
- 価格・コスト推移の分析。
- 食品以外（医薬品・処方箋・防災備品など）に特化した管理機能。
- 多言語対応。
- AI による消費予測・自動発注提案。
- 家計簿アプリ・スマートホーム機器との連携。
- グループのネスト構造（複数グループを束ねる上位グループ・組織階層）。v1.0.0 では「1 ユーザーが複数グループに所属」までで対応する。

## 7. 用語集

| 用語              | 定義                                                                       |
| ----------------- | -------------------------------------------------------------------------- |
| ローリングストック | 日常的に消費しながら買い足し、常に一定量の備蓄を保つ方式                   |
| グループ          | 在庫を共有する単位。世帯・家族・シェアハウス等を想定                       |
| オーナー          | グループ作成者または管理者。メンバー招待・権限変更・削除の権限を持つ       |
| 必要備蓄量        | 人数 × 想定日数（× カテゴリ別係数）で算出する目標在庫量                    |
| 消費期限          | 安全に食べられる期限。過ぎたら廃棄推奨                                     |
| 賞味期限          | 美味しく食べられる期限。過ぎても直ちに不可食ではない                       |
| ローカルファースト | デバイスのローカルストレージを正とし、クラウドへ同期する設計方針           |
